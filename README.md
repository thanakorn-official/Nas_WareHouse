# Nas Warehouse

ระบบจัดการคลังสินค้าแบบเต็มรูปแบบ ประกอบด้วย React/Vite client และ Express/PostgreSQL server

## โครงสร้างโปรเจกต์

- `client/` — หน้าเว็บจัดการคลังสินค้า
- `server/` — REST API และการเชื่อมต่อ PostgreSQL
- `docker-compose.yml` — PostgreSQL สำหรับการพัฒนาในเครื่อง

## เริ่มต้นใช้งาน

### 1. เปิดฐานข้อมูล

```bash
docker compose up -d db
```

### 2. ตั้งค่า server

กำหนดค่าฐานข้อมูลใน `server/.env` โดยใช้ `DB_USER`, `DB_HOST`, `DB_NAME`, `DB_PASSWORD`, `DB_PORT` และ `PORT`

ติดตั้งแพ็กเกจและเริ่ม API:

```bash
cd server
npm install
npm run dev
```

`npm run dev` ใช้ `node --watch index.js` และ `npm start` ใช้สำหรับเริ่ม server แบบปกติ

### 3. เริ่ม client

```bash
cd client
npm install
npm run dev
```

เปิด URL ที่ Vite แสดงใน terminal โดย client จะเรียก API ที่ `http://localhost:5000` เป็นค่าเริ่มต้น หากต้องการเปลี่ยนให้กำหนด `VITE_API_URL`

## ความสามารถ

- หน้าแรกแสดงรายการโปรเจค และแยกการจัดการสินค้าออกจากกันตามโปรเจค
- สร้างโปรเจคด้วยรหัสและชื่อ เช่น `coj`; ระบบออกรหัสสินค้าเป็น `coj-0001`, `coj-0002` ตามลำดับ
- จัดการสินค้าในโปรเจค พร้อม Tags, Custom Fields, ผู้เพิ่ม และวันเวลาที่สร้าง
- นำเข้าสินค้าจากไฟล์ `.xlsx` ได้สูงสุด 500 รายการต่อครั้ง
- Dashboard แสดงสัดส่วนสินค้าแยกตามสถานะภายในโปรเจค
- จัดการสถานะแบบเพิ่ม แก้ไข ลบ เปิด/ปิดใช้งาน และกำหนดสี
- โปรเจคเดิมถูกย้ายไปยังโปรเจคเริ่มต้น `main` ระหว่าง migration โดยไม่ลบสินค้าเดิม
- Migration ฐานข้อมูลที่ทำงานซ้ำได้ โดยลบคอลัมน์ราคาเดิมและเพิ่มความสัมพันธ์สถานะให้กับสินค้า
- ระบบสมาชิกพร้อมล็อกอินและกำหนดสิทธิ์ตามบทบาท

## สมาชิกและบทบาท

เมื่อเปิดระบบครั้งแรก ให้สร้างบัญชี Owner จากหน้าเว็บ โดยใช้ชื่อผู้ใช้และรหัสผ่าน ไม่ต้องใช้อีเมล จากนั้น Owner เพิ่มหรือแก้ไขสมาชิกและกำหนดบทบาทได้ที่เมนู **สมาชิก**

- **Owner** — จัดการโปรเจค สินค้า สถานะสินค้า และสมาชิก
- **Manager** — สร้างโปรเจค และดู เพิ่ม แก้ไข ลบสินค้าพร้อมดูสถานะสินค้า
- **Employee** — ดู เพิ่ม และแก้ไขสินค้า พร้อมดูสถานะสินค้า

ก่อนนำเข้าไฟล์ Excel ให้กำหนดแต่ละคอลัมน์เป็นชื่อสินค้า, Product ID, จำนวน, สถานะ, Tag, Fields หรือไม่ใช้ก็ได้ ระบบจะตรวจหารหัสสินค้าแบบ `COJ3267-0001` จากคอลัมน์ชื่อให้อัตโนมัติ และสามารถแก้ Product ID ได้ภายหลัง รหัสต้องไม่ซ้ำกันภายในโปรเจค

ระบบเก็บรหัสผ่านแบบแฮชและตรวจสิทธิ์ที่ API ด้วย บัญชีที่ปิดใช้งานจะเข้าสู่ระบบไม่ได้ และระบบจะไม่อนุญาตให้ปิด Owner คนสุดท้าย

ชื่อผู้ใช้ต้องไม่ซ้ำกันและใช้เข้าสู่ระบบได้ สมาชิกเดิมในฐานข้อมูลจะได้รับชื่อผู้ใช้ชั่วคราวรูปแบบ `member_<รหัสสมาชิก>` และยังเข้าสู่ระบบด้วยอีเมลเดิมได้จนกว่าจะเปลี่ยนชื่อผู้ใช้

ตั้งค่า `AUTH_SECRET` ใน `server/.env` เพื่อให้ token สำหรับล็อกอินใช้ต่อได้หลังรีสตาร์ต server หากไม่กำหนด ระบบจะสร้าง secret ชั่วคราวใหม่เมื่อเริ่ม server
